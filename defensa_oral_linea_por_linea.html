1. Arquitectura y Fundamentos de AgroSense

AgroSense es un sistema de agricultura inteligente diseñado para capturar telemetría agroclimática de sensores en parcelas agrícolas, procesar mediciones en tiempo real, evaluar reglas agronómicas automáticas y disparar alertas preventivas para proteger la producción.

Estructura Arquitectónica en 3 Capas:
  • Capa de Controladores (Controller): Expone los endpoints REST, recibe las solicitudes HTTP, aplica validaciones automáticas con Bean Validation y devuelve respuestas HTTP con códigos de estado estándar (200, 201, 400, 404).
  • Capa de Servicios (Service): Contiene la lógica de negocio, orquesta las transacciones, evalúa las reglas agronómicas y garantiza la idempotencia (evitando alertas duplicadas en 120s).
  • Capa de Persistencia (Repository & Model): Define las entidades mapeadas con JPA/Hibernate y repositorios que interactúan con 4 esquemas aislados en PostgreSQL: gestion, sensores, mediciones y alertas.

3. Archivo 2: Entidad JPA (Medicion.java)

Representa una medición climática histórica persistida en la tabla mediciones.mediciones.

package com.agrosense.model; import jakarta.persistence.*; import java.time.OffsetDateTime; import java.util.UUID; @Entity @Table(name = "mediciones", schema = "mediciones") public class Medicion { @Id @Column(name = "id", nullable = false, updatable = false) private UUID id; @Column(name = "temperatura", nullable = false) private Double temperatura; @Column(name = "humedad", nullable = false) private Double humedad; @Column(name = "fecha", nullable = false) private OffsetDateTime fecha; @Column(name = "sensor_id", nullable = false) private UUID sensorId; @PrePersist protected void onCreate() { if (this.id == null) this.id = UUID.randomUUID(); if (this.createdAt == null) this.createdAt = OffsetDateTime.now(); } }
Líneas Código Explicación Técnica para la Defensa
L7 @Entity Indica a JPA/Hibernate que esta clase representa una tabla en la base de datos relacional.
L8 @Table(name="mediciones", schema="mediciones") Mapea la entidad al esquema PostgreSQL mediciones. Esto demuestra aislamiento por dominios, clave en arquitecturas de microservicios.
L11-L12 @Id, @Column(..., updatable=false) Define id como Clave Primaria (Primary Key). updatable=false garantiza que el ID nunca sea modificado después de crearse.
L13 private UUID id; Uso de identificadores universales únicos (UUID v4 de 128 bits). Previene colisiones en entornos distribuidos y evita la predictibilidad de los IDs autoincrementales.
L15-L18 Double temperatura, humedad Variables agroclimáticas obligatorias requeridas por el sensor para evaluar las reglas en tiempo real.
L21 private OffsetDateTime fecha; Manejo de fechas con zona horaria (UTC) conforme al estándar ISO-8601. Evita discrepancias horarias entre el cliente y el servidor.
L24 private UUID sensorId; Referencia lógica al sensor emisor. Al estar en esquemas desacoplados, no se usa Foreign Key rígida entre esquemas, respetando el principio de microservicios.
L26-L30 @PrePersist protected void onCreate() Hook del ciclo de vida de JPA. Se ejecuta automáticamente antes de insertar el registro en PostgreSQL: si el cliente no mandó ID, el servidor genera un UUID.randomUUID() de forma segura.

4. Archivo 3: DTO con Java Records (MedicionCreateDTO.java)

Demuestra el uso de características de Java moderno para implementar objetos de transferencia de datos (DTO) inmutables y seguros.

package com.agrosense.dto; import jakarta.validation.constraints.*; import java.time.OffsetDateTime; import java.util.UUID; public record MedicionCreateDTO( @NotNull(message = "La temperatura es obligatoria") Double temperatura, @NotNull(message = "La humedad es obligatoria") @DecimalMin(value = "0.0", message = "La humedad no puede ser menor a 0%") @DecimalMax(value = "100.0", message = "La humedad no puede superar 100%") Double humedad, @NotNull(message = "La fecha y hora es obligatoria") OffsetDateTime fecha, @NotNull(message = "El ID del sensor es obligatorio") UUID sensorId ) { // Constructor compacto para validaciones de borde matematico public MedicionCreateDTO { if (temperatura != null && (temperatura.isNaN() || temperatura.isInfinite())) { throw new IllegalArgumentException("La temperatura debe ser un numero finito"); } if (humedad != null && (humedad.isNaN() || humedad.isInfinite())) { throw new IllegalArgumentException("La humedad debe ser un numero finito"); } } }
Líneas Código Explicación Técnica para la Defensa
L7 public record MedicionCreateDTO(...) Característica de Java moderno: Un record genera de forma nativa e inmutable los atributos privados y final, el constructor canónico, los métodos getters (temperatura()), equals(), hashCode() y toString() sin necesidad de librerías externas como Lombok.
L8-L9 @NotNull(message="...") Anotación de Jakarta Bean Validation. Si el cliente envía un JSON sin temperatura, Spring rechaza la petición con código HTTP 400 antes de tocar la base de datos.
L12-L13 @DecimalMin("0.0"), @DecimalMax("100.0") Validación de rango físico: la humedad relativa porcentual solo tiene sentido físico en el intervalo [0.0%, 100.0%]. Valores como -5% o 150% son rechazados automáticamente.
L21-L28 public MedicionCreateDTO { ... } Constructor Compacto del Record: Valida que los números no sean NaN (Not a Number) ni infinitos. Previene ataques de denegación o corrupción de cálculos matemáticos.

5. Archivo 4: Controlador REST (MedicionController.java)

Expone los servicios HTTP para registrar y consultar mediciones de sensores.

@RestController @RequestMapping("/api/mediciones") public class MedicionController { private final MedicionService medicionService; // Inyeccion de dependencias por constructor public MedicionController(MedicionService medicionService) { this.medicionService = medicionService; } @PostMapping public ResponseEntity<MedicionProcessingResponseDTO> create( @Valid @RequestBody MedicionCreateDTO dto) { MedicionProcessingResponseDTO response = medicionService.create(dto); return ResponseEntity.status(HttpStatus.CREATED).body(response); } @PostMapping("/{id}/procesar") public ResponseEntity<MedicionProcessingResponseDTO> procesarReintento( @PathVariable UUID id) { return ResponseEntity.ok(medicionService.procesarReintento(id)); } }
Líneas Código Explicación Técnica para la Defensa
L1 @RestController Combina @Controller y @ResponseBody. Transforma automáticamente las respuestas de los métodos en formato JSON para el cliente.
L2 @RequestMapping("/api/mediciones") Define la URL base para este recurso. Cumple con el estándar RESTful (sustantivos en plural).
L7-L9 public MedicionController(MedicionService ...) Inyección de Dependencias por Constructor: Es el estándar recomendado por Spring. Garantiza que la clase sea inmutable (campo final), facilita las pruebas unitarias con mocks y evita dependencias nulas.
L11-L13 @Valid @RequestBody MedicionCreateDTO dto @RequestBody deserializa el cuerpo JSON de la petición HTTP en el DTO. @Valid activa automáticamente las reglas de validación (@NotNull, @DecimalMin). Si fallan, dispara una excepción antes de ejecutar el método.
L15 HttpStatus.CREATED Devuelve el código de estado HTTP 201 Created según la especificación RFC del protocolo HTTP para la creación exitosa de un recurso.
L18-L20 @PostMapping("/{id}/procesar") Endpoint para reprocesamiento idempotente. Si por un corte de red el servicio de alertas no pudo registrar una alerta, este endpoint permite reintentar el procesamiento sin duplicar datos.

6. Archivo 5: Lógica de Reglas Agronómicas (AgronomicRulesService.java)

Núcleo agronómico del sistema. Evalúa las condiciones ambientales y genera las recomendaciones técnicas preventivas.

@Service public class AgronomicRulesService { public static final double REGLA_HUMEDAD_BAJA_UMBRAL = 30.0; public static final double REGLA_HUMEDAD_ALTA_UMBRAL = 80.0; public static final double REGLA_TEMPERATURA_ALTA_UMBRAL = 35.0; public List<AlertaCreateDTO> evaluarReglas(Double temperatura, Double humedad, UUID cultivoId, OffsetDateTime fecha) { List<AlertaCreateDTO> alertas = new ArrayList<>(); OffsetDateTime fechaActual = fecha != null ? fecha : OffsetDateTime.now(); // Regla 1: Humedad baja (humedad < 30) if (humedad != null && humedad < REGLA_HUMEDAD_BAJA_UMBRAL) { alertas.add(new AlertaCreateDTO("RIEGO", "Revisar la necesidad de riego.", AlertaPrioridad.ALTA, fechaActual, cultivoId)); } // Regla 2: Humedad alta (humedad > 80) if (humedad != null && humedad > REGLA_HUMEDAD_ALTA_UMBRAL) { alertas.add(new AlertaCreateDTO("EXCESO_HUMEDAD", "Revisar el drenaje antes de regar.", AlertaPrioridad.MEDIA, fechaActual, cultivoId)); } // Regla 3: Calor excesivo (temperatura > 35) if (temperatura != null && temperatura > REGLA_TEMPERATURA_ALTA_UMBRAL) { alertas.add(new AlertaCreateDTO("CALOR", "Revisar condiciones por temperatura elevada.", AlertaPrioridad.ALTA, fechaActual, cultivoId)); } return alertas; } }
Líneas Código Explicación Técnica para la Defensa
L1 @Service Indica a Spring que esta clase es un Bean de la capa de servicio que encapsula lógica de negocio y debe ser gestionado por el contenedor IoC (Inversion of Control).
L4-L6 public static final double UMBRAL_... Definición de constantes inmutables (30.0%, 80.0%, 35.0°C). Evita "números mágicos" hardcodeados en el código y facilita su mantenimiento o calibración.
L11-L14 if (humedad < 30.0) Regla de Estrés Hídrico: Condición estricta menor que 30%. Dispara alerta preventiva tipo RIEGO con prioridad ALTA para advertir riesgo de marchitez en el cultivo.
L16-L19 if (humedad > 80.0) Regla de Saturación Hídrica: Condición mayor que 80%. Dispara alerta tipo EXCESO_HUMEDAD con prioridad MEDIA para advertir riesgo de asfixia radicular y proliferación de hongos.
L21-L24 if (temperatura > 35.0) Regla de Estrés Térmico: Condición mayor que 35°C. Dispara alerta tipo CALOR con prioridad ALTA por evaporación crítica.
L26 return alertas; Devuelve la lista de alertas generadas. Si se cumplen calor y sequía a la vez (ej. 38°C y 20%), el método genera y retorna ambas alertas de forma independiente.

7. Archivo 6: Repositorio JPA e Idempotencia (AlertaRepository.java)

Gestiona la persistencia de alertas y contiene la consulta JPQL para la ventana de deduplicación temporal.

@Repository public interface AlertaRepository extends JpaRepository<Alerta, UUID> { List<Alerta> findByCultivoIdOrderByFechaDesc(UUID cultivoId); @Query("SELECT a FROM Alerta a WHERE a.cultivoId = :cultivoId AND a.tipo = :tipo " + "AND a.fecha BETWEEN :fromTime AND :toTime ORDER BY a.fecha DESC") List<Alerta> findDuplicates( @Param("cultivoId") UUID cultivoId, @Param("tipo") String tipo, @Param("fromTime") OffsetDateTime fromTime, @Param("toTime") OffsetDateTime toTime ); }
Líneas Código Explicación Técnica para la Defensa
L2 extends JpaRepository<Alerta, UUID> Spring Data JPA implementa automáticamente en tiempo de ejecución las operaciones CRUD completas (save(), findById(), delete(), paginación) sin escribir una sola línea de SQL.
L4 findByCultivoIdOrderByFechaDesc(...) Método de consulta derivado (Query Method): Spring analiza el nombre del método y genera automáticamente la consulta SQL: SELECT * FROM alertas WHERE cultivo_id = ? ORDER BY fecha DESC.
L6-L8 @Query("SELECT a FROM Alerta a WHERE ...") Consulta JPQL (Java Persistence Query Language): Consulta orientada a objetos (opera sobre la entidad Alerta a y no sobre tablas físicas).
L9-L14 findDuplicates(...) con BETWEEN Control de Idempotencia: Busca si en una ventana de 120 segundos ya existe una alerta del mismo tipo para ese cultivo. Si existe, no se inserta una duplicada, evitando saturar al productor agrícola con cientos de notificaciones repetidas.

8. Archivo 7: Manejador Global de Errores (GlobalExceptionHandler.java)

Centraliza la captura de excepciones para devolver respuestas JSON estandarizadas ante fallos del cliente o del servidor.

@RestControllerAdvice public class GlobalExceptionHandler { @ExceptionHandler(ResourceNotFoundException.class) public ResponseEntity<AppErrorResponse> handleNotFound(ResourceNotFoundException ex, HttpServletRequest req) { AppErrorResponse response = AppErrorResponse.of("NotFoundError", ex.getMessage(), null, req.getRequestURI()); return ResponseEntity.status(HttpStatus.NOT_FOUND).body(response); } @ExceptionHandler(MethodArgumentNotValidException.class) public ResponseEntity<AppErrorResponse> handleValidation(MethodArgumentNotValidException ex, HttpServletRequest req) { Map<String, String> errors = new HashMap<>(); for (FieldError error : ex.getBindingResult().getFieldErrors()) { errors.put(error.getField(), error.getDefaultMessage()); } AppErrorResponse response = AppErrorResponse.of("ValidationError", "Error en validacion de datos", errors, req.getRequestURI()); return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(response); } }
Líneas Código Explicación Técnica para la Defensa
L1 @RestControllerAdvice Anotación basada en AOP (Programación Orientada a Aspectos). Intercepta cualquier excepción ocurrida en cualquier controlador de la aplicación.
L4-L8 @ExceptionHandler(ResourceNotFoundException.class) Captura cuando un recurso no existe (ej. un sensor con un UUID que no figura en la base). Devuelve HTTP 404 Not Found con un mensaje limpio en lugar de un volcado feo de error de servidor (500).
L10-L19 handleValidation(MethodArgumentNotValidException) Captura las violaciones de Jakarta Validation (por ejemplo, si mandan humedad = -10%). Recorre los FieldErrors y devuelve un mapa detallando exactamente qué campo falló y por qué, con HTTP 400 Bad Request.

9. Preguntas Frecuentes de Profesores y Respuestas de Alto Nivel

❓ Pregunta 1: "¿Por qué usaron UUID en lugar de un Long autoincremental en las entidades?"

Respuesta: "En arquitecturas modernas y orientadas a microservicios, los IDs autoincrementales generan dos problemas graves: primero, acoplan la generación de claves a un único motor de base de datos centralizado; segundo, exponen riesgos de seguridad ya que permiten deducir cuántos registros existen mediante un ataque de enumeración (adivinar IDs 1, 2, 3...). Al utilizar UUID v4 de 128 bits, los identificadores son generados de forma distribuida por el servidor con una probabilidad de colisión prácticamente nula y sin exponer secuencias internas."

❓ Pregunta 2: "¿Por qué la entidad Alerta NO tiene un atributo medicionId si una medición es la que dispara la alerta?"

Respuesta: "Por fidelidad estricta al Diagrama de Clases del Dominio original. En el modelo de negocio, una alerta pertenece a un Cultivo (el cultivo es el activo afectado que necesita atención agronómica), no a un número de telemetría. La relación entre Medición y Alerta es una dependencia funcional en la capa de servicios, pero persistir medicionId en Alerta hubiese sido inventar un atributo ajeno al modelo acordado."

❓ Pregunta 3: "¿Qué es un Java Record y qué ventaja aportó a los DTOs?"

Respuesta: "Los Records son una característica estándar de Java moderno. Representan portadores de datos inmutables y transparentes. Reemplazan las clases boilerplate tradicionales eliminando la necesidad de escribir getters, constructores, equals y hashcode, y garantizan que los datos viajen inmutables desde que ingresan por la capa web hasta que son procesados."

❓ Pregunta 4: "¿Cómo evitaron que un sensor enviando datos continuamente sature la base de datos de alertas repetidas?"

Respuesta: "Implementamos un mecanismo de Idempotencia Temporal en el servicio de alertas. Cuando se evalúa una condición crítica (por ejemplo, humedad menor a 30%), antes de persistir la alerta se realiza una consulta JPQL con BETWEEN para verificar si en una ventana de 120 segundos ya se emitió una alerta del mismo tipo para ese cultivo. Si ya existe, se omite el duplicado."

❓ Pregunta 5: "¿Por qué en pom.xml el compiler target es Java 21 si instalamos y ejecutamos con el JDK 25?"

Respuesta: "Cumplimos con el uso del entorno Java 25: el proyecto está compilado con el compilador de Java 25 y se ejecuta sobre la máquina virtual (JVM) de Java 25. Sin embargo, frameworks empresariales como Spring Boot 3 emplean la librería ASM para el escaneo de componentes en tiempo de ejecución. Configurar el target en versión de bytecode compatible (21) le permite a Spring Framework leer los archivos compilados sin que el ClassReader aborte con un error de versión, asegurando máxima estabilidad y portabilidad."
